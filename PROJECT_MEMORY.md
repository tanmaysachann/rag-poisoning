# Sentinel RAG project memory

Last reviewed: 2026-09-26. Primary source: `Presentation.pdf` (38 slides). Full execution plan: `IMPLEMENTATION_PLAN.md`; measured claims: `REPORT_EVIDENCE.md`.

## Goal

Build the major project titled **Implementation of an LLM-Based RL Policy-Driven Secure RAG Framework for Dynamic Context Sanitization and Poisoning Attack Mitigation**. The finished project must include an offline document-poisoning research environment, a trained PPO edit policy, a multi-signal detector, integrity-aware secure RAG inference, evaluation against attack and utility baselines, and a demonstrable web console. The attack work stays in a self-contained research corpus.

## Presentation commitments

- Slides 3-7: corpus poisoning and indirect prompt injection; RL attack generation; multi-signal detection; zero-trust RAG; SHA-256 integrity checks; leave-one-out counterfactual testing; SLM-driven SRQ.
- Slides 16-18: MS MARCO v1.1 passages and NQ-Open questions; reproducible data pipeline.
- Slides 19-27: document-edit MDP; state vector advertised as 1,556 dimensions; actions `INSERT`, `PARAPHRASE`, `SYNONYM`, `DELETE`, `STOP`; operation/position/payload policy heads; edit-effect memory; shaped reward; PPO with two value heads.
- Slides 20, 28-30: shield -> critic -> secure generation pipeline, with retrieval, integrity, anomaly and behavioral checks, classifier filtering, isolated generation, audit trail, and a demonstration UI.
- Slides 31-34: Python/PyTorch, Hugging Face models, BM25+dense+RRF, optional FAISS, quantized LLM, Kaggle GPU as a possible training environment.
- Slides 9-14 and 35-37: literature and citations require verification before final submission. Slide 8 maps the work to SDGs 4, 9, 16, and 17.

## Implementation status (2026-09-25)

- The original offline Review-1 demo is still available. P0 configuration contracts were repaired and an isolated rebuild smoke test was added.
- A revision-pinned MS MARCO v1.1 benchmark has 350 train, 75 validation, and 75 untouched test query/passages; NQ-Open has 50 separate challenge queries. Training and validation use hashing embeddings and a frozen test split.
- The attack harness stages insertions/replacements in separate corpora. Versioned integrity manifests reject unknown or altered documents; the demo has a post-index tamper switch. A locally cached, optional Qwen 0.5B answer backend was run on ten validation examples; strict citation validation abstained on all ten, so the extractive answerer remains the default.
- The research detector uses eight cheap features and a validation-calibrated threshold. At a 4% clean false-positive rate on 75 validation documents, greedy same-template recall was 100%; stealth answer substitution recall was 5.3%. These are distinct attack families.
- The full validation extractive defense experiment found greedy attack success 86.7% before / 0% after defense, but only 20% clean answer recovery. Stealth substitution was 16% before / 14.7% after, with 1.3% clean answer recovery. Clean-corpus alias-match answer accuracy is only 22.7%, with 48% abstention. Selective LOO runs on ambiguous accepted answer sources and is logged, but rarely triggers; it does not independently quarantine documents.
- The edit MDP now has five actions, a versioned v3 774-dimensional hashing state, masks, constraints, terminal retrieval/answer reward, edit-effect cache, and a masked factored PPO policy with two value heads. Early STOP and repeated-identical-payload reward loopholes were closed. A 200-episode undefended CPU PPO run reached 89.3% validation attack success, tying fixed insertion. A separate 200-episode defender-aware run used the frozen detector and an accepted-ingest replacement surface; it reached 14.7% defended attack success, tying fixed answer-span substitution. Neither policy beats its matched simple baseline.
- Latest full suite: 43 passing tests and 17 subtests. The isolated offline rebuild previously passed with 25 clean documents, 5 poisoned documents, and 6 PDF reports. The frontend JavaScript syntax, UI element bindings, API summary availability, sealed v1 test verifier, and v2 benchmark validator passed.

## Remaining gaps and constraints

- `config.py` now provides `RESULTS_DIR` and `QUERIES_PATH`. User changes present at project start were preserved.
- Integrity mismatches and unknown documents now fail closed when defense is on. A hash only proves integrity relative to a protected, trusted manifest; accepted-ingest poisoning still needs content analysis.
- The live demo's S1 metric is a document-embedding Mahalanobis proxy. Separate MiniLM encoder-internal and Qwen answer-generator decoder prefill probes were measured; their evidence does not retroactively change the demo signal.
- `config.USE_LLM` can route to a role-separated local Transformers backend, and real Qwen 0.5B loading and a 10-case clean diagnostic have run. Strict citations caused abstention on the original prompt; broader answer-quality and adversarial prompt validation remain outstanding.
- Existing cross-validation precomputes clean distribution statistics on all 25 clean documents before LOOCV and uses one tightly authored attack set. Future metrics need fold-safe fitting and held-out attack/query/source families.
- A slide-7 SRQ module computes the query-plus-SLM-response semantic vocabulary quotient. Real Qwen response generation, train-clean calibration, and 75-case validation are now complete; the signal did not meet detection needs. The console has a read-only Research view of saved validation summaries; the original demo remains separate. The local API served that view successfully over HTTP, but visual browser inspection was unavailable because no browser instance was connected.
- Cached MiniLM validation retrieval reached support recall@1 97.3% and recall@5 98.7%, versus hashing 66.7% and 86.7%; mean measured query time rose from about 0.5 ms to 11.3 ms. This is a small 75-passage validation corpus. A train-only MiniLM sentence ranker raised exact alias match on validation from 28.0% (the original extractor with MiniLM) to 54.7% and selected labeled support in 98.7% of cases. Its stricter threshold was calibrated after withholding support from training questions; on validation, it still answered 7/75 cases after labeled support was removed, versus 1/75 for the conservative extractor. Some remaining passages may be answer-bearing, so this is an abstention stress test, not a proven false-answer rate. The ranker remains experimental because the paired security evaluation found poor stealth defense.
- A 50-question NQ-Open challenge against the 75-passage validation corpus found 44 queries whose exact answer aliases are absent from every passage. The strict ranker abstained on 20/44 (45.5%) of those, answering the rest. Alias absence is a lexical stress condition, not proof that every answer was unsupported or wrong.
- Transfer experiments reused the original 75 greedy and 75 stealth validation attack documents with MiniLM retrieval and the learned ranker. Greedy attack success was 41.3% undefended and 0% defended; defended clean alias recovery was 52.0%. Stealth attack success was 28.0% both undefended and defended, with 5.3% attack quarantine and 2.7% clean alias recovery. Median per-case latency was about one second on this CPU, including per-case reindexing. Thus the improved answer selector increases utility on overt attacks but does not mitigate accepted-ingest answer substitution.
- `scripts/trusted_ingest.py` now previews added/changed/missing IDs and requires an exact reviewed corpus digest before sealing. Manifest writes are atomic, optional HMAC signing remains supported, and replacement of an existing manifest requires an explicit CLI flag. This is an operator workflow; it does not automate truth approval.
- Real cached MiniLM encoder probes now extract layer-3 hidden states and last-layer attention, with a reference distribution fitted on 100 training clean pairs and thresholds calibrated on 50 other training clean pairs. On 75 validation pairs per family, layer Mahalanobis recall was 0% greedy and 6.7% stealth; attention deviation recall was 0% greedy and 4% stealth. Clean validation FPR was 9.3% for the layer score and 0% for attention. These probes are not useful standalone and are not wired into quarantine. They are encoder internals, not the answer generator's decoder internals.
- The Research console now has a read-only case explorer for all four saved 75-case validation runs (greedy/stealth × hashing/MiniLM ranker). It shows both answers, attack rank, integrity state, quarantine decision, and clean-alias recovery without retraining or reindexing on page load.
- `evaluation/summarize_validation.py` now derives descriptive Wilson 95% intervals and query-paired bootstrap reductions from the four raw validation defense runs. They are stored in `results/validation_intervals.json`; the validation set has informed development, so these are not final unbiased confidence claims.
- `LITERATURE_AUDIT.md` maps all 24 printed references to primary sources, corrects a chain of swapped arXiv IDs, and identifies the three missing slide-14 sources. The Information Fusion article is specifically about knowledge-graph RAG. `Presentation.pdf` still needs a corrected export.

## Execution principles

1. Keep the current Review-1 demo runnable while building the full research system in modules.
2. Separate attack training, detector training, and final evaluation sets by query and source document; never train against final held-out cases.
3. Record model/dataset revisions, random seeds, hashes, hardware, and latency/cost for reproducibility.
4. Distinguish measured implementation from presentation concepts. Do not claim 5% false-positive rate from a sigmoid threshold alone or call a deterministic proxy an SLM/hidden-state measurement.
5. Preserve a CPU/offline demonstration path; use GPU jobs for expensive PPO/LLM experiments when available.
