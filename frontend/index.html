INTERPRETATION

Integrity catches edits made after a trusted snapshot. Accepted-ingest misinformation needs content checks. The research detector catches overt query-matched insertion and misses most subtle answer substitutions. The learned answer selector improves exact alias match but answers more often when labeled support is removed. The separate Secure Query path runs signed corpus and source-origin checks with the joint S1-S4 gate; paired validation found it blocked no additional attack successes and blocked one clean answer. The Five-Case Demo and research workbench retain their separate serving paths.

V26 SCANNER ARCHITECTURE

What happens when you scan a document

This is the path used by the live V26 scanner. It assesses a candidate passage against the question and a supplied trusted reference, then returns a source-risk decision with reasons. The reference must be authenticated outside this scanner.

THREE SIGNAL BRANCHES

All paths inspect the same candidate. The supplied reference guides comparison but must be authenticated by the operator.

PATH A / LEARNED CONTENT RISKQuestion + reference + candidate
A1Windowed MiniLM

Three-label reference-conditioned classifier; candidate is read in overlapping 250-token windows and the maximum poison probability is retained.

A2Behavioral model

Eight features include embedding distance, isolation score, relevance spike, instruction and URL patterns, authority cues, and query overlap.

A3Fluency + calibration

A second signal model combines behavioral risk with fluency features. Both learned scores are mapped to tails of frozen clean-score distributions.

A4Reference-relative fusion

Fusion = -ln(min(clean tails)). V25 compares the candidate fusion with the reference's own fusion score.

Outputs: V3 risk; candidate fusion; reference fusion; candidate-reference margin
PATH B / SOURCE AND IDENTITYCandidate + pinned source index
B1Region search

Terms from the opening, ending, and sometimes middle of the passage query the pinned 2,681,468-passage NQ FTS5 index.

B2Containment comparison

Retrieved neighbors are hash-checked. Normalized similarity and longest-match source coverage detect a known passage embedded in edited text.

B3Optional identity

If the operator supplies an independently pinned expected SHA-256, compare it with the UTF-8 candidate digest.

Outputs: source match, containment score, calibrated flag, optional digest mismatch
PATH C / V26 ROLE-BOUNDARY SIGNALReference-preserved tail + candidate
C1Attack surface

If candidate starts with the reference, inspect the appended tail; otherwise inspect the candidate. Use the final 1,200 characters.

C2Role features

Extract system and assistant markers across bracket, chat, XML, and Markdown forms, plus directive, target, quote, and role-transition features.

C3Trained probability

A supervised logistic model scores those features. The role flag needs both a system marker and probability at least 0.50.

Outputs: role probability, system-marker indicator, trained role flag
LAYER 1 / FROZEN V25

Four independent review triggers

V3 behavioralrisk ≥ 0.75
Reference-relative fusioncandidate ≥ 4.272 and margin ≥ 0.50
Source containmentscore ≥ calibrated threshold
Identity, if suppliedcandidate SHA-256 ≠ pinned digest

Any one trigger makes V25 review the passage.

LAYER 2 / V26 EXTENSION

Role-aware decision

V26 review = V25 review OR (system marker AND role probability ≥ 0.50)

The response returns pass/review plus learned, reference-relative, integrity, identity, and role evidence. This endpoint screens a document; it does not generate a RAG answer.
